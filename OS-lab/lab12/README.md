# 段页式存储管理实验脚手架

## 实验目标与算法概览

这个实验不是单纯“把几张表打印出来”，而是让你把段页式存储管理里的三件核心事情串起来：

1. 主存里哪些物理块空闲，哪些已经被占用。
2. 一个作业被装入后，它的每一段、每一页分别落到了哪个物理块。
3. 给定逻辑地址后，系统怎样一步步把它换算成物理地址。

如果你写对了，程序行为应该体现出下面这条主线：

- 分配时：先看空闲块够不够，再为每一页找物理块，最后更新位示图、段表、页表。
- 回收时：按作业名找到作业，再把它占用的所有块释放掉。
- 地址转换时：先找作业，再查段表，再查页表，最后做物理地址计算。

这也是这次实验真正想让你掌握的内容：  
**位示图负责“物理块管理”，段表和页表负责“逻辑地址到物理块的映射”，三者必须保持一致。**

## 你需要自己完成什么

这份工程最终保留的是教学脚手架，所以 `src/` 里的关键算法都留成了 `TODO`。你要完成的不是“补一点打印语句”，而是把下面这些真正有学习价值的逻辑自己写出来：

- 在 `src/main.c` 里补全主交互流程。
- 在 `src/mem_model.c` 里完成位示图初始化、作业分配、作业回收、地址转换。
- 在 `src/io_view.c` 里把位示图、段表、页表和地址转换结果输出成接近实验截图的风格。

建议你把这份脚手架当成“老师给的半成品”，而不是现成答案。  
如果你一上来就看 `docs/reference_solution.md`，这份工程对你的学习价值会直接下降很多。

## 先别急着写代码，先搞清楚你要维护的状态

这个实验最容易写乱的原因，是很多同学一上来就开始写菜单，结果真正的状态关系没想清楚。  
你应该先明确这几个对象分别管什么：

- `bitmap_words` / `block_used`
  表示每个物理块是否空闲。
- `job_list_head`
  串起所有已经装入的作业。
- `job_node`
  记录一个作业的名字、大小、段数，以及这个作业的所有段。
- `segment_entry`
  记录某一段有多少页。
- `page_entry`
  记录某一页对应哪个物理块。

你后面写任何功能，本质上都在维护这几类状态的一致性。  
如果你发现“页表写对了，但位示图没更新”或者“位示图清零了，但作业链表里还留着旧作业”，那就是算法没写完整。

## 目录职责

- `include/seg_paged_mem.h`
  共享数据结构、全局状态和公共函数声明。先读它，搞清楚实验中有哪些对象。
- `include/seg_paged_io.h`
  输出层接口。你可以从这里看出程序最终需要展示哪些信息。
- `src/main.c`
  主控制流程。这里保留了题面要求的 `Print / distribute / recycle / menu / init`。
- `src/mem_model.c`
  核心算法区。位示图、作业链表、段表、页表相关逻辑都应该落在这里。
- `src/io_view.c`
  输出层脚手架。这里负责菜单、位示图、段表/页表、地址转换结果展示。
- `data/`
  样例输入和边界条件输入，不只是“给你跑一次程序”，更是你调试时的检查点。
- `scripts/run_case.exp`
  交互回放脚本。适合在你补完一部分逻辑后快速回放样例。
- `docs/reference_solution.md`
  已验证过的完整参考实现。建议最后再看。
- `docs/case_reference_output.md`
  关键案例的期望结果摘要，适合你手动对照运行结果。
- `docs/report.md`
  实验报告模板。
- `docs/questions.md`
  思考题，适合写实验总结时回看。

## 推荐实现顺序

不要从菜单开始堆功能，按下面顺序做会稳很多。

### 第一步：先把主存模型初始化跑通

对应文件：
- `src/mem_model.c`
- `src/main.c`

先做的事情：
- 正确读取主存大小、字长、块长。
- 正确计算块数和位示图行数。
- 初始化空闲块计数。
- 先做“全 0 位示图”版本。

这一步你要验证：
- 程序一启动就能打印初始位示图。
- 剩余空闲块数等于总块数。

这一步最常见的坑：
- 把“字长”和“块长”的意义混了。
- 位示图行列计算写错，导致打印越界。
- 内存大小不能整除块长时没有想清楚怎么处理。

### 第二步：只做分配，不做回收

对应文件：
- `src/mem_model.c` 里的 `mem_allocate_job`
- `src/main.c` 里的 `distribute`

先做的事情：
- 统计所有段一共需要多少页。
- 检查空闲块数是否足够。
- 扫描空闲块，拿到足够多的块号。
- 构造作业结点，填好段表和页表。
- 更新位示图和剩余空闲块数。

这一步你要验证：
- `case_sample.txt` 能装入 `job1`。
- 分配前后空闲块数变化正确。
- 页表里的块号和位示图里的 `1` 对得上。

这一步最常见的坑：
- 作业大小和总页数容量之间没校验。
- 页表填好了，但没更新位示图。
- 位示图更新了，但没把作业挂到链表里。
- 重名作业重复装入。

### 第三步：再做回收

对应文件：
- `src/mem_model.c` 里的 `mem_recycle_job`
- `src/main.c` 里的 `recycle`

先做的事情：
- 按作业名在链表里找目标作业。
- 遍历它的段表和页表，把对应块全部释放。
- 更新剩余空闲块数。
- 从链表里删掉这个作业。

这一步你要验证：
- `case_multi_job.txt` 中回收 `job1` 后，相关块重新变成 `0`。
- 回收不存在的作业时，能输出明确中文提示。

这一步最常见的坑：
- 只删链表，不恢复位示图。
- 只清了部分页，漏掉某些段。
- 删除链表结点时把指针断坏。

### 第四步：最后做地址转换

对应文件：
- `src/mem_model.c` 里的 `mem_translate`
- `src/main.c` 中菜单项 `3`

先做的事情：
- 按作业名找到目标作业。
- 检查段号是否合法。
- 再检查页号是否合法。
- 再检查页内偏移是否合法。
- 查页表得到物理块号。
- 计算物理地址。

这一步你要验证：
- `case_address_ok.txt` 能得到正确块号和物理地址。
- `case_address_oob.txt` 能给出“段号/页号/偏移越界”之类的错误提示。

这一步最常见的坑：
- 越界检查顺序反了。
- 物理地址公式写错。
- 误把“页号”直接当“块号”。

### 第五步：再回头优化输出

等功能正确后，再去调整 `src/io_view.c` 的显示风格，让它更接近你截图里的中文提示和表头。  
不要一开始花很多时间抠格式，否则你很容易把调试重心放错。

## 调试时该怎么用这些样例

`data/` 不是摆设。你可以按下面方式使用：

- `case_sample.txt`
  主流程样例，先验证能不能完成一次正常装入。
- `case_small_fit.txt`
  刚好装满，适合检查“边界刚好成立”时有没有误判。
- `case_multi_job.txt`
  连续装入再回收，适合检查链表和位示图是否同步更新。
- `case_address_ok.txt`
  合法地址转换。
- `case_address_oob.txt`
  越界地址转换。
- `case_no_space.txt`
  主存不足。
- `case_recycle_missing.txt`
  回收不存在作业。

如果你每次改完算法都只跑主样例，很容易把 bug 留到最后。  
正确做法是：每补完一个功能，就立刻跑对应边界案例。

## 截图、题面框架和脚手架之间的差异

- 题面里给的是 C++ 风格骨架，这里已经改成 C11 的 `include/ + src/` 结构，更适合课程实验分层实现。
- 题面提到“随机初始化位示图”，但你给的截图更接近“初始全空闲”的展示，所以脚手架默认建议先实现全 0 初始化，等主流程对了再考虑随机化。
- 题面原始框架更像“分配/回收演示”，而你给的截图和需求里明确包含地址转换演示，所以这里把地址转换放进了菜单主流程。

如果老师最后检查的是“截图风格的交互顺序”，你应该优先让自己的程序行为和截图一致，而不是死守题面那段不完整骨架。

## 构建、运行与回放命令

构建学生脚手架：

```bash
make student
```

```bash
./bin/student_lab
```

```bash

```


## 什么时候看参考解，怎么对照才不浪费

建议按这个顺序：

1. 先自己把一个功能补到能跑。
2. 用 `data/` 里的对应案例测出问题。
3. 如果卡住，再先看 `docs/case_reference_output.md`，确认你到底是“流程错了”还是“显示错了”。
4. 只有在你已经明确卡在算法细节时，再看 `docs/reference_solution.md`。

这样看参考解，你是在“带着问题去核对”；  
如果一开始就直接照抄，你后面一旦被问“为什么回收时必须先遍历页表”就很容易答不上来。

## 自查清单

在你准备对照参考解之前，先逐条问自己：

- 程序启动后，初始空闲块数是不是等于总块数？
- 分配一个作业后，位示图中的 `1` 是否和页表里的块号严格对应？
- 分配失败时，是否没有留下半更新状态？
- 回收一个作业后，它占用的所有块是否都恢复成 `0`？
- 回收失败时，位示图和链表是否保持不变？
- 地址转换时，是否严格按“作业 -> 段号 -> 页号 -> 页内偏移”的顺序检查？
- 物理地址计算是否真的是 `块号 * 块长 + 页内偏移`？
- 输出提示是否已经足够接近题目截图里的中文风格？
- 你现在是因为“确实卡住”才去看参考解，还是只是想跳过思考？

如果前 8 条你都答不上来，说明你还不该去看参考解。
