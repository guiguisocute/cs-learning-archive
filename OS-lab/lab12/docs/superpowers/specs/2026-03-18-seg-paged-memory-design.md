# 段页式存储管理实验设计说明

## 1. 目标

本实验用于模拟段页式存储管理中的主存分配、回收与地址转换过程。项目最终交付分为两层：

- 一份已经验证过的参考实现，用于教师演示、学生对照和后续答疑。
- 一份保留 `TODO` 的教学脚手架，用于学生自己完成核心算法。

本次用户明确要求：

- 语言改为 C11。
- 项目结构采用 `include/ + src/ + data/ + docs/ + scripts/`。
- 终端提示、表头和交互顺序尽量贴近用户提供的截图。
- 需要在程序菜单中直接演示地址转换，而不是只写在文档中。
- 需要提供更多边界条件样例。

## 3. 行为范围

程序需要支持以下能力：

1. 输入主存大小、字长、块长。
2. 初始化位示图，并输出位示图与剩余空闲块信息。
3. 装入作业：
   - 输入作业名
   - 输入作业总大小
   - 输入段数
   - 输入每段页数
   - 在位示图中查找空闲物理块并分配
   - 生成段表与页表
4. 回收作业：
   - 按作业名定位作业
   - 释放对应物理块
   - 更新位示图与剩余空闲块数
5. 地址转换演示：
   - 输入作业名、段号、页号、页内偏移
   - 检查段号、页号和偏移是否合法
   - 输出对应的物理块号和物理地址
6. 查看当前位示图与作业分配情况。

## 4. 与题面框架的兼容策略

题面给出了以下函数名：

- `Print()`
- `distribute()`
- `recycle()`
- `menu()`
- `init()`

这些函数名在教学脚手架中会被保留，作为学生需要实现或继续完善的主要入口。  
同时，内部实现会做命名规范化，避免继续使用题面中的低质量标识符。

## 5. 命名规范化

内部实现采用更清晰的 C 风格命名。README 中会提供命名对照表。当前计划如下：

- `ye` -> `page_entry`
- `duan` -> `segment_entry`
- `work` -> `job_node`
- `table` -> `bitmap_words`
- `head` -> `job_list_head`

若有必须与题面一致的外部接口，则仅保留外部接口名称，内部数据和辅助函数一律规范化。

## 6. 模块边界

### `include/seg_paged_mem.h`

定义：

- 主存配置
- 位示图模型
- 作业、段表、页表数据结构
- 公共函数声明

### `include/seg_paged_io.h`

定义：

- 菜单输出
- 位示图输出
- 作业和地址转换结果输出接口

### `src/mem_model.c`

负责：

- 初始化位示图
- 空闲块统计
- 空闲块分配与释放
- 作业链表挂接与删除
- 地址转换辅助

### `src/io_view.c`

负责：

- 打印中文菜单
- 打印位示图、作业表、段表、页表
- 输出错误提示和地址转换结果

### `src/main.c`

负责：

- 读取用户输入
- 组织交互流程
- 调用 `Print / distribute / recycle / menu / init`

### `src/reference_impl.c`

用于：

- 先形成并验证完整参考实现
- 验证完成后，代码内容迁移到 `docs/reference_solution.md`

## 7. 交互流程

交互流程以用户截图为目标风格：

1. 启动后按顺序输入主存大小、系统字长、块长。
2. 初始化完成后输出位示图及剩余空闲块数。
3. 菜单至少包含：
   - `1` 内存分配
   - `2` 内存回收
   - `3` 地址转换
   - `4` 查看当前内存状态
   - `0` 退出
4. 分配作业时继续输入：
   - 作业名
   - 作业总大小
   - 段数
   - 每段页数
5. 地址转换时继续输入：
   - 作业名
   - 段号
   - 页号
   - 页内偏移

## 8. 数据样例

除题面样例外，增加以下边界条件：

- 刚好装满的场景
- 多作业装入后回收某一作业
- 地址转换成功场景
- 段号越界、页号越界、页内偏移越界
- 空闲块不足
- 回收不存在的作业

`scripts/run_case.exp` 需要支持：

- 单个案例回放
- 批量回放 `data/` 下多个案例

推荐按以下顺序落地：

2. 完成参考实现所需的数据结构与内存模型。
3. 完成交互与打印，使输出尽量贴近截图。
4. 用样例和边界数据验证完整实现。
5. 将完整实现转存到文档。
6. 回退项目源码为保留 `TODO` 的教学脚手架。
7. 补全文档、样例、脚本和编辑器配置。

## 11. 风险与取舍

- 用户截图信息有限，无法逐字复刻所有输出，因此目标是“整体交互顺序与标签风格接近”，而不是伪造固定输出。
- 题面给出的 `size` 与“段数/每段页数”的关系可能存在二义性。实现中会显式校验页数对应容量，避免作业总大小与分页需求冲突时悄悄吞掉错误。
- 教学脚手架要保持可编译，因此 `TODO` 版本会提供安全桩函数和必要的基础头文件，但不会保留完整算法。
