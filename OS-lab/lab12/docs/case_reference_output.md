# 参考输出摘要

本文档记录的是已经验证过的参考实现所呈现的关键结果，方便你和自己的脚手架版本做人工对照。

## case_sample.txt

- 初始位示图全为 `0`
- `job1` 分配成功
- 段 `0` 的页号 `0..9` 映射到物理块 `0..9`
- 段 `1` 的页号 `0..19` 映射到物理块 `10..29`
- 分配后剩余空闲块数从 `1024` 变为 `994`

## case_multi_job.txt

- `job1` 与 `job2` 可以连续装入
- 回收 `job1` 后，位示图中它占用的块恢复为 `0`
- 会输出 `作业 job1 回收成功。`

## case_address_ok.txt

- 地址转换成功
- `job1` 的 `(段号=1, 页号=1, 页内偏移=0)` 对应物理块 `3`
- 物理地址为 `3`

## case_address_oob.txt

- 会输出 `地址转换失败：页号越界。`

## case_no_space.txt

- 第一项作业装入后剩余空闲块数不足
- 第二项作业会输出 `主存空间不足，无法装载！`

## 新增边界数据的预期目标

下面这些新增数据主要用于你实现算法后的自测，不是要求当前 TODO 脚手架就必须跑出完整结果。

### case_duplicate_job.txt

- 第一份 `job1` 可以正常装入
- 第二次装入同名 `job1` 时，应明确拒绝，而不是覆盖旧作业

### case_page_capacity_mismatch.txt

- 当 `总页数 * 块长 < 作业大小` 时，应报“页数容量不足”或等价错误

### case_address_segment_oob.txt

- 地址转换时应报“段号越界”

### case_address_offset_oob.txt

- 地址转换时应报“页内偏移越界”

### case_multi_recycle_chain.txt

- 连续回收 `job1`、`job2` 后，位示图中相关块都应恢复为 `0`
- 空闲块数应回到初始值
