# 样例参考输出

下面的结果来自已经验证通过的参考实现，适合在你完成 `src/main.c` 后手工对照。

## 关键结论

- `3` 个物理块
  - `jobA` 的 FIFO 缺页率应为 `75.00`
  - `jobB` 的 LRU 缺页率应为 `60.00`
- `4` 个物理块
  - `jobC` 的 FIFO 缺页率应为 `50.00`
  - `jobD` 的 LRU 缺页率应为 `40.00`
- `1` 个物理块
  - `case_single_frame.txt` 的 FIFO/LRU 缺页率都应为 `87.50`
- 全部访问同一页
  - `case_all_same_page.txt` 的 FIFO/LRU 缺页率都应为 `16.67`
- 物理块数大于不同页面数
  - `case_frames_ge_pages.txt` 的 FIFO/LRU 缺页率都应为 `42.86`
- 热点集合切换
  - `case_alternating_hotset.txt` 的 FIFO 缺页率应为 `75.00`
  - `case_alternating_hotset.txt` 的 LRU 缺页率应为 `66.67`
- 短访问串
  - `case_short_sparse.txt` 的 FIFO/LRU 缺页率都应为 `75.00`

## 边界测试说明

- `case_single_frame.txt`
  用来观察最极端的物理块压力。只有当前访问页与上一页相同才会命中。

- `case_all_same_page.txt`
  用来确认“首次装入后连续命中”的逻辑是否正确。这个数据非常适合排查错误地重复计数缺页的问题。

- `case_frames_ge_pages.txt`
  用来验证“物理块充足时不应发生替换”。如果这组数据仍然频繁缺页，说明命中判定或装入逻辑有问题。

- `case_alternating_hotset.txt`
  用来观察热点页切换时两种算法的差异。虽然这组数据上 LRU 也不算特别低，但它应明显优于 FIFO。

- `case_short_sparse.txt`
  用来检查短访问串、末尾退出和空位输出，不依赖长过程表也能快速排查实现错误。
