# 请求分页式存储管理中的页面置换算法实验报告

## 一、实验目的

1. 理解请求分页式存储管理的基本思想，掌握页面调入与缺页中断的处理流程。
2. 掌握 FIFO（先进先出）页面置换算法的原理与实现，理解"最早进入内存的页面最先被淘汰"的策略。
3. 掌握 LRU（最近最久未使用）页面置换算法的原理与实现，理解"最长时间未被访问的页面最先被淘汰"的策略。
4. 通过对比 FIFO 与 LRU 在相同页面访问串上的缺页率差异，加深对页面置换策略选择与局部性原理之间关系的理解。

## 二、实验内容

编写一个请求分页式存储管理的页面置换算法模拟程序。程序从终端读取物理块数，在交互式菜单中选择 FIFO 或 LRU 算法后，输入作业名、页面长度和页面访问顺序，模拟页面调度过程，输出每一步的物理块状态、缺页标记和缺页率。

结合当前代码实现，本实验实际完成了以下内容：

1. 通过全局变量管理物理块数（`frame_count_limit`）、作业名（`job_name`）、页面长度（`job_length`）和页面访问序列（`page_seq`）。
2. 通过 `solve1()` 实现 FIFO 页面置换算法，使用循环队列头指针 `fifo_head` 确定淘汰位置。
3. 通过 `solve2()` 实现 LRU 页面置换算法，使用 `last_used[]` 时间戳数组追踪每个物理块的最近访问时刻。
4. 通过 `print()` 输出调度过程表，包括时间步编号、各物理块在每一步的页面内容、缺页标记行（`+`）、缺页页号行和缺页率。
5. 通过 `copy_snapshot()` 在每一步记录物理块状态快照，通过 `find_page()` 判断页面命中与缺页。
6. 通过 7 组测试用例验证经典序列、单物理块、全命中、无替换、LRU 优势、4 物理块和短序列等场景下的正确性。

## 三、实验过程概述

本实验分为 5 个阶段：理解与分析、数据结构设计、核心程序实现、调试与结果验证、实验总结。

各阶段任务概括如下：

1. 理解与分析阶段：明确请求分页的核心概念，重点理解"缺页时物理块已满则需选择一个页面淘汰"的决策过程，以及 FIFO 和 LRU 两种策略在淘汰决策上的本质差异。
2. 数据结构设计阶段：根据实验要求理解全局状态变量和快照数组的布局，确定输入、调度和输出三个模块的数据流。
3. 核心程序实现阶段：完成 `solve1()`（FIFO）、`solve2()`（LRU）和 `print()` 三个核心函数，以及 `copy_snapshot()` 和 `find_page()` 两个辅助函数。
4. 调试与结果验证阶段：使用 7 组测试数据运行程序，检查每步物理块状态、缺页标记、缺页页号和缺页率是否与参考输出一致。
5. 实验总结阶段：根据程序实现与测试结果，分析两种算法的特点与适用场景，整理形成实验报告。

## 四、理解与分析

请求分页式存储管理是操作系统虚拟内存机制的核心组成部分。其基本思想是：进程的页面不必全部预先装入内存，而是在运行过程中按需调入。当 CPU 访问的页面不在内存中时，产生缺页中断，操作系统将该页面从外存调入内存的某个物理块中。如果所有物理块已被占满，则需要选择一个已在内存中的页面将其淘汰（换出），为新页面腾出空间。

本实验的核心问题是：**当缺页发生且物理块已满时，应该淘汰哪个页面？**FIFO 和 LRU 给出了两种不同的回答。

FIFO 的决策依据是页面进入内存的时间顺序。它维护一个类似循环队列的结构，每次淘汰驻留时间最长的页面——即最早进入内存的那个页面。FIFO 的优点是实现简单，只需一个队首指针即可确定淘汰对象；缺点是不考虑页面的实际使用情况，一个虽然最早进入但仍被频繁访问的页面照样会被淘汰。

LRU 的决策依据是页面最近一次被访问的时间。它为每个物理块维护一个"最近访问时刻"的时间戳，每次淘汰时间戳最小的页面——即距离当前时刻最久未被访问的页面。LRU 的优点是利用了"局部性原理"：最近被访问过的页面在近期再次被访问的概率较高，最久未被访问的页面再被访问的概率较低；缺点是需要在每次页面命中时更新时间戳，实现开销高于 FIFO。

从当前源码可以看出，实验已经落地为以下实现思路：

1. 用 `frame_snapshot[MAX_FRAMES][MAX_PAGES]` 二维数组记录每一步的物理块状态快照，行表示物理块、列表示时间步。
2. 用 `page_fault[]` 和 `fault_page[]` 两个一维数组分别记录每步是否缺页及缺页时调入的页号。
3. 在 `solve1()` 中用局部数组 `frames[]` 表示当前物理块内容，用 `fifo_head` 作为循环队首指针。缺页且物理块已满时，替换 `frames[fifo_head]` 位置的页面，然后将 `fifo_head` 向前推进一位（取模循环）。
4. 在 `solve2()` 中用 `last_used[]` 数组为每个物理块记录最近访问时刻。命中时更新该位置的时间戳为当前步号；缺页且物理块已满时，扫描 `last_used[]` 找到最小值对应的位置进行替换。

本实验的核心难点在于以下三个关键问题：

1. 快照记录的完整性。无论当前步是命中还是缺页，都必须在该步结束时调用 `copy_snapshot()` 记录物理块状态。如果只在缺页时记录快照，命中步的物理块列将全为空白，导致过程表不完整。
2. LRU 命中时的时间戳更新。LRU 算法最容易写错的地方是"命中时忘记更新 `last_used[]`"。如果只在缺页装入时设置时间戳，算法实际上退化为 FIFO（因为时间戳只反映了进入顺序而非最近访问顺序），两种算法的结果将会一样。
3. FIFO 队首指针的推进时机。`fifo_head` 应当在每次替换后推进一位，而不是在每次缺页时推进。当物理块未满时，新页面直接追加到 `frames[used_frames]`，不需要移动 `fifo_head`；只有物理块已满、发生替换时，才将 `fifo_head` 指向下一个位置。

## 五、数据结构设计

本实验使用全局静态变量管理所有运行状态。关键变量及其作用如下表所示：

| 变量 | 类型 | 作用说明 |
| --- | --- | --- |
| `job_name` | `char[MAX_NAME_LEN]` | 当前作业名称 |
| `frame_count_limit` | `int` | 物理块总数，决定内存容量 |
| `job_length` | `int` | 页面访问序列长度 |
| `page_seq[]` | `int[MAX_PAGES]` | 页面访问序列 |
| `frame_snapshot[][]` | `int[MAX_FRAMES][MAX_PAGES]` | 快照数组，`[i][j]` 表示第 j 步时第 i 个物理块中的页号，-1 表示空 |
| `page_fault[]` | `int[MAX_PAGES]` | 缺页标记数组，1 表示该步发生缺页 |
| `fault_page[]` | `int[MAX_PAGES]` | 缺页页号数组，记录缺页时调入的页号，-1 表示无缺页 |
| `fault_total` | `int` | 缺页总次数 |
| `current_algorithm` | `int` | 当前算法标识（1=FIFO，2=LRU） |
| `has_schedule_result` | `int` | 是否已完成调度（控制 print 的输出行为） |

在 `solve1()` 和 `solve2()` 中还使用了局部变量：

| 变量 | 所属函数 | 作用说明 |
| --- | --- | --- |
| `frames[]` | `solve1` / `solve2` | 当前物理块内容数组 |
| `used_frames` | `solve1` / `solve2` | 已使用的物理块数 |
| `fifo_head` | `solve1` | FIFO 循环队首指针，指向下一个被替换的位置 |
| `last_used[]` | `solve2` | LRU 时间戳数组，记录每个物理块最近一次被访问的时间步 |

快照数组 `frame_snapshot` 的设计是本实验的关键。它的行表示物理块编号，列表示时间步编号，在每一步结束后由 `copy_snapshot()` 将当前 `frames[]` 内容复制到对应列中。这种设计使得 `print()` 只需逐行逐列遍历数组即可输出完整的调度过程表，不需要重新运行调度逻辑。

与银行家算法实验中使用结构体集中管理状态不同，本实验选择使用全局静态变量加局部变量的方式，这是因为本实验只有单一作业的调度流程，不涉及多个并发实体的状态交互，使用全局变量足够清晰且与老师原始框架一致。

## 六、核心程序实现

本实验采用"主函数控制交互菜单，功能函数分模块实现"的结构。整体流程是：先读取物理块数，进入菜单循环，根据用户选择调用 FIFO 或 LRU 调度函数，再调用 print 输出结果。

主要函数及其作用如下表所示：

| 函数名 | 主要作用 | 所处阶段 |
| --- | --- | --- |
| `out()` | 显示交互式菜单 | 交互控制 |
| `input()` | 读取作业名、页面长度和页面访问序列 | 输入阶段 |
| `solve1()` | 执行 FIFO 页面置换算法 | 核心调度阶段 |
| `solve2()` | 执行 LRU 页面置换算法 | 核心调度阶段 |
| `print()` | 输出调度过程表、缺页标记和缺页率 | 输出阶段 |

辅助函数：

| 辅助函数 | 主要作用 |
| --- | --- |
| `reset_run_state()` | 清零 `fault_total`、`page_fault`、`fault_page` 和 `frame_snapshot`，为新一轮调度做准备 |
| `copy_snapshot()` | 将当前 `frames[]` 内容复制到 `frame_snapshot` 的第 `step` 列 |
| `find_page()` | 在 `frames[]` 中线性查找指定页号，返回下标或 -1 |

FIFO 算法（`solve1()`）的核心步骤如下：

1. 调用 `reset_run_state()` 清零所有结果数组，设置 `current_algorithm = 1`。
2. 初始化局部 `frames[]` 数组、`used_frames = 0`、`fifo_head = 0`。
3. 对页面访问序列中的每一页 `page_seq[i]`：
   - 调用 `find_page()` 判断是否命中。
   - 若缺页：设置 `page_fault[i] = 1`、`fault_page[i] = page_seq[i]`、`fault_total++`。
   - 若物理块未满（`used_frames < frame_count_limit`），将新页面追加到 `frames[used_frames++]`。
   - 若物理块已满，替换 `frames[fifo_head]`，然后 `fifo_head = (fifo_head + 1) % frame_count_limit`。
   - 无论命中还是缺页，都调用 `copy_snapshot()` 记录当前物理块状态。
4. 设置 `has_schedule_result = 1`。

LRU 算法（`solve2()`）的核心步骤如下：

1. 调用 `reset_run_state()` 清零所有结果数组，设置 `current_algorithm = 2`。
2. 初始化局部 `frames[]`、`last_used[]`、`used_frames = 0`。
3. 对页面访问序列中的每一页 `page_seq[i]`：
   - 调用 `find_page()` 判断是否命中。
   - 若命中：更新 `last_used[hit_index] = i`（关键步骤）。
   - 若缺页：设置缺页标记和统计。
   - 若物理块未满，追加新页面并设置 `last_used[used_frames] = i`。
   - 若物理块已满，遍历 `last_used[]` 找到最小值的下标 `replace_index`，替换该位置的页面并更新其时间戳。
   - 调用 `copy_snapshot()` 记录快照。
4. 设置 `has_schedule_result = 1`。

`print()` 函数的输出结构如下：

1. 标题行：`************作业{name}{algorithm}调度进入主存页的过程************`。
2. 时间步编号行：`0  1  2  ...  (job_length-1)`，每列宽 3 字符。
3. 物理块内容行：共 `frame_count_limit` 行，每行输出对应物理块在每步的页号，空位输出空格。
4. 缺页标记行：缺页位置输出 `+`，命中位置输出空格。
5. 缺页页号行：缺页位置输出调入的页号，命中位置输出空格。
6. 缺页率行：`缺页率为：{fault_total * 100.0 / job_length}`，保留两位小数。

关键实现点汇总：

| 关键实现点 | 具体做法 | 目的 |
| --- | --- | --- |
| FIFO 淘汰策略 | 用 `fifo_head` 循环指针指向下一个被替换的位置 | 模拟先进先出队列 |
| LRU 淘汰策略 | 用 `last_used[]` 记录时间戳，找最小值对应位置 | 淘汰最久未被访问的页面 |
| LRU 命中更新 | 命中时 `last_used[hit_index] = i` | 确保时间戳反映真实的最近访问时刻 |
| 快照完整记录 | 命中和缺页后都调用 `copy_snapshot()` | 保证过程表每一列都有完整数据 |
| 状态初始化 | 每次调度前 `reset_run_state()` 清零全部结果 | 避免上一轮调度的残留数据干扰 |

## 七、调试与结果验证

本实验在 `Ubuntu-24.04.1LTS-WSL2 x86_64 GNU/Linux` 环境下完成，使用 `gcc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0` 编译器，通过 `make` 构建生成可执行文件 `build/paging_lab`。编译选项包含 `-std=c11 -Wall -Wextra -Wpedantic -Werror`，确保代码无任何警告。

调试过程中主要关注以下几个问题：

1. FIFO 的队首指针是否只在替换时推进——如果在物理块未满时也推进 `fifo_head`，会导致替换位置错位。
2. LRU 命中时是否更新了 `last_used[]`——如果遗漏，LRU 退化为 FIFO，两种算法的缺页率将完全相同。
3. 快照是否在每一步都记录——如果只在缺页步记录，命中步的物理块列将全为 -1，输出为空白。
4. `frame_snapshot` 的行列含义是否一致——行表示物理块、列表示时间步，如果反转会导致输出转置。
5. 缺页率的分母是否使用 `job_length` 而非 `fault_total`——百分比的计算基数应为总页面访问次数。

为验证程序正确性，使用了 7 组测试数据进行测试，结果如下表所示：

| 用例 | 物理块数 | 页面数 | 主要特点 | FIFO 缺页率 | LRU 缺页率 |
| --- | ---: | ---: | --- | --- | --- |
| `sample_case_01.in` | 3 | 20 | 经典教材序列 `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1` | 75.00% | 60.00% |
| `case_4_frames.in` | 4 | 20 | 同上序列，增加到 4 物理块 | 50.00% | 40.00% |
| `case_single_frame.in` | 1 | 8 | 单物理块，连续不同页面 | 87.50% | 87.50% |
| `case_all_same_page.in` | 3 | 6 | 全部访问同一页面 5 | 16.67% | 16.67% |
| `case_no_replace.in` | 5 | 7 | 物理块充足，3 个不同页面无需替换 | 42.86% | 42.86% |
| `case_lru_advantage.in` | 3 | 12 | 热点集合切换 `1 2 3 1 4 1 2 5 1 2 3 4` | 75.00% | 66.67% |
| `case_short_sparse.in` | 2 | 4 | 短序列，4 种不同页面 | 75.00% | 75.00% |

从测试结果可以看出：

1. 在经典教材序列（`sample_case_01.in`）中，3 个物理块下 FIFO 缺页率为 75.00%，LRU 缺页率为 60.00%，LRU 明显优于 FIFO。这是因为该序列中存在页面 0 被频繁访问的特征，LRU 能通过时间戳更新将页面 0 保留在内存中，而 FIFO 不考虑访问频率，仍按进入顺序淘汰页面 0。
2. 当物理块数从 3 增加到 4（`case_4_frames.in`）时，FIFO 从 75.00% 降到 50.00%，LRU 从 60.00% 降到 40.00%，两种算法都显著受益于更多的物理块。增加物理块意味着更多页面可以同时驻留在内存中，减少了淘汰和重新装入的次数。
3. 在单物理块（`case_single_frame.in`）极端场景下，FIFO 和 LRU 的缺页率完全相同（87.50%），因为只有 1 个物理块时，两种算法的淘汰策略完全退化——永远只能淘汰唯一的那个页面，只有连续重复访问同一页面才能命中。
4. 在全命中（`case_all_same_page.in`）场景下，两种算法的缺页率均为 16.67%（6 次访问中只有第 1 次缺页），验证了"首次装入后持续命中"的正确性。
5. 在无替换（`case_no_replace.in`）场景下，5 个物理块、只有 3 个不同页面（0、1、2），物理块始终不会满，缺页仅发生在首次装入时（前 3 步），缺页率为 42.86%（3/7），两种算法无差异。
6. 在 LRU 优势场景（`case_lru_advantage.in`）中，序列 `1 2 3 1 4 1 2 5 1 2 3 4` 包含"页面 1 被频繁回访"的特征。LRU 能识别这一局部性并将页面 1 保留在内存中，缺页率 66.67%；FIFO 按进入顺序淘汰，无法利用这一信息，缺页率 75.00%。
7. 在短序列（`case_short_sparse.in`）中，2 个物理块、4 步访问 4 种页面，缺页率均为 75.00%。由于页面全部不同且物理块太少，两种算法没有区别。

以 `sample_case_01.in` 为例详细分析 FIFO 过程：初始物理块为空，前 3 步依次装入页面 7、0、1，均为缺页。第 4 步访问页面 2，物理块已满，`fifo_head` 指向位置 0（最早进入的页面 7），替换为 2，`fifo_head` 推进到 1。第 5 步访问页面 0，命中（仍在物理块中），不替换。第 6 步访问页面 3，缺页，`fifo_head` 指向位置 1（页面 0），替换为 3，如此循环。最终 20 步中 15 次缺页，缺页率 75.00%。

## 八、实验总结

通过本次实验，我对请求分页式存储管理和页面置换算法有了更深入的理解。与教材中的算法描述相比，自己实现并调试后更容易把握以下几个关键点：

1. FIFO 和 LRU 的本质区别在于淘汰决策的信息来源。FIFO 只关注页面进入内存的时间，不考虑后续访问情况，实现简单但性能受限；LRU 关注页面最近一次被访问的时间，能利用局部性原理做出更好的淘汰决策，但需要额外维护时间戳信息。在 `case_lru_advantage.in` 中，页面 1 被频繁回访，LRU 识别出这一特征将其保留在内存中，而 FIFO 因为页面 1 进入时间最早反而将其淘汰，导致更多缺页。
2. 物理块数量对缺页率的影响非常显著。同一访问串在 3 个物理块下 FIFO 缺页率为 75%，增加到 4 个物理块后降至 50%，说明增加内存容量是降低缺页率最直接的手段。但值得注意的是，FIFO 算法存在 Belady 异常——增加物理块数有时反而会增加缺页率，这是 FIFO 不具备栈性质的固有缺陷。LRU 不存在这个问题，它是一种栈算法。
3. 在极端场景下两种算法趋于一致。当只有 1 个物理块或所有页面相同时，算法选择不影响结果，因为此时淘汰策略没有实质性的选择空间。这提醒我们，算法的优劣只在"有选择余地"的场景下才体现出来。
4. 快照记录是本实验最容易遗漏的细节。调度算法本身逻辑并不复杂，但"每一步都必须记录物理块状态"这一要求容易在命中分支中被忽略。最初调试时曾出现命中步物理块列为空白的问题，定位发现是只在缺页分支调用了 `copy_snapshot()`，修正后在循环末尾统一调用即解决。
5. LRU 中命中时更新时间戳是关键。如果只在缺页装入时设置 `last_used[]`，算法实际上退化为 FIFO，因为时间戳仅反映了页面首次进入的时间而非最近访问时间。在对比测试中，遗漏这一更新会导致 FIFO 和 LRU 在所有用例上产生完全相同的缺页率，这是定位该 bug 的快速方法。

从实现角度看，本实验练习了循环队列（FIFO 的 `fifo_head` 指针）、线性扫描最值（LRU 查找最小时间戳）、二维快照数组管理和格式化输出对齐等基础编程方法。7 组测试用例的运行结果表明，当前程序已经能够正确处理经典序列、单物理块、全命中、无替换、LRU 优势、多物理块和短序列等场景。

在实际操作系统中，纯 LRU 的实现代价较高（需要在每次内存访问时更新时间戳），因此实际系统通常使用近似 LRU 算法，如"时钟算法"（Clock），通过硬件访问位来近似追踪最近访问情况，在性能和开销之间取得平衡。这也是本实验可以进一步探索的方向。
